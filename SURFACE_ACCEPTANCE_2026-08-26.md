# Adaptive Surface Acceptance — 2026-08-26

## Outcome

The production package compiles one deterministic finite-plan grammar into three materially different consumer surfaces. Travel is deep enough to carry the signature transaction; renovation and event prove that adaptation changes structure, measures, language, time, and available action—not only labels or colour.

## Compiler proof

- `compileSurfaceManifest` accepts only the closed component grammar.
- Every profile binding resolves against its own kernel state.
- Surface intent is bound to the active profile revision.
- Unknown components, executable/template text, stale revision, and attempts to hide mandatory controls are refused.
- Candidate state forces option comparison into the manifest.
- Staged state forces a non-hideable approval panel into the manifest.
- Every accepted manifest receives a reproducible SHA-256 identity.

## Projection proof

| Profile | Time structure | Primary measures | Structural lane | Decision vocabulary |
|:--|:--|:--|:--|:--|
| Travel | Calendar | trip forecast, extension cost, remaining buffer | dated trip timeline | viable routes, flexibility, commitments |
| Renovation | Phases | completion, contingency, change-order pressure | critical phase lane | recovery plans, handover, trades |
| Event | Run-of-show | guest count, capacity, show forecast | run-of-show sequence | show plans, guest experience, vendors |

The compiled manifests also differ in stages, field bindings, preferred components, profile actions, nouns, hero copy, and hash.

## Browser transaction proof

Chrome 151 loaded all three projections without console warning or error. Event acceptance exercised the complete visible transaction:

1. selected `Protect the guest experience`;
2. displayed an exact revision-1 approval statement;
3. forecast delta was −A$530 and post-change contingency A$930;
4. the human-only control approved and atomically applied the exact staged option;
5. revision advanced to 2 and receipt `receipt_f8dc924f` was rendered;
6. reload restored the event profile, guest count 115, venue capacity 120, show forecast A$270, contingency A$930, and the same accepted receipt.

The first reload run exposed a profile-preference defect: accepted event truth reopened inside the travel projection. The runtime now persists only the device-local active-profile preference while keeping staged candidates and authority volatile. Repeating the run preserved the event projection and receipt.
